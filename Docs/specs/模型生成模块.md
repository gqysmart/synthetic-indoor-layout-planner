# 模型生成模块

FloorPlanAR → 现实采集入口（用 AR 得到 2D 户型图）。

Plan2Scene → AI 转换模型（把 2D 户型 → 3D 室内场景）。

3D-FRONT → 数据源（支撑训练/验证上述模型）。

## Step 1. 数据采集/输入

工具：FloorPlanAR [floorPlanAR]()

用户操作：用手机/平板 AR 扫描房间，得到 2D 平面图（FloorPlan）。

输出：房间墙体、门窗的 结构化 2D 户型图。

## Step 2. 数据增强 & 训练支撑

数据集：3D-FRONT

用途：

提供大规模 2D–3D 户型对齐样本，作为 Plan2Scene 的训练集/验证集。

提供家具库（种类、位置、尺寸），保证 AI 生成结果逼真。

输出：带标注的 训练/验证样本库。

## Step 3. AI 自动建模

模型：Plan2Scene

输入：用户上传的 2D 户型图（来自 FloorPlanAR 或 CAD 图）。

输出：生成一个完整的 3D 室内场景（墙体 + 家具摆放）。

依赖：Plan2Scene 的效果好坏取决于是否有足够的 3D-FRONT 数据支撑。

## Step 4. 后期优化（可选）

在 Blender / SweetHome3D / FreeCAD 中打开结果：

调整家具风格（现代/中式/北欧）。

改变材质和渲染效果。

用户可手动 fine-tune。

## UE5 里这三种 参数生成几何的方式：

🔹 1. Procedural Mesh Component (PMC)

定位：底层 API，用顶点 + 三角形索引自己拼网格。

灵活性：最高，可以生成任何几何。

难度：需要写 C++ 或 Blueprint 节点手动填充点、面。

应用：

数学函数生成几何（螺旋、波浪曲面）

实时修改顶点（破碎、变形效果）

👉 优点：完全可控。
👉 缺点：开发复杂，像自己造一个网格编辑器。

🔹 2. Geometry Script

定位：UE5 新出的几何操作框架（C++/Blueprint）。

灵活性：比 PMC 高效，内置很多几何工具（拉伸、布尔、切割、倒角）。

难度：中等，用 API/Blueprint 调用，而不是手写网格点。

应用：

参数化生成基本体（立方体、圆柱、管道）

运行时修改几何（加洞、拉伸墙体）

做类似 Revit 那种参数建模

👉 优点：带现成算子，开发效率高。
👉 缺点：还比较新，文档不算多。

🔹 3. PCG Framework (Procedural Content Generation)

定位：内容生成系统（UE5.2+），更像“规则引擎”。

灵活性：偏中高，主要是用 Graph 定义规则 → 自动生成布置。

难度：可视化编辑，拖拽节点，学习曲线比代码低。

应用：

城市/森林/道路自动生成

室内布局（按房间尺寸自动放家具）

随机化生成大场景

👉 优点：适合大规模自动化布置。
👉 缺点：本质是“生成/布置已有网格”，不是几何核心运算。

🎯 总结对比
特性	Procedural Mesh	Geometry Script	PCG Framework
层级	底层顶点操作	几何 API/运算	规则/内容生成
灵活性	无限制	中高	中等（偏布置）
适合谁	数学/算法控	参数化建模	场景布置/随机生成
难度	最高	中等	最低（可视化图形）
几何来源	纯代码生成	参数 + API	规则 + 资产库（网格）

👉 所以：

做 BIM/室内设计原型 → Geometry Script 最合适（墙体/房间参数化）。

做大规模布置（森林/家具/城市场景） → PCG Framework。

做底层实验/自定义形状 → Procedural Mesh Component。
